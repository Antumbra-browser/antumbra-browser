<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| antumbra.js → browser pref store | Prefs set here become the browser's security defaults; a wrong pref name is silently ignored, quietly removing a protection. |
| pref names → upstream tree | Upstream removes and renames prefs; a stale pref in antumbra.js silently disappears. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Tampering | prefs/antumbra.js | mitigate | pref audit CI job (audit-prefs.py, plan 01-06) checks every pref name against the upstream tree on every push; stale pref fails the build. |
| T-01-02-02 | Information Disclosure | network.trr.uri placeholder | accept | Default resolver (Quad9) is noted as a placeholder; first-run wizard (plan 01-05) overwrites it with the user's choice. Quad9 is a legitimate privacy-respecting resolver in the interim. |
| T-01-02-03 | Tampering | cookiebanners.service.mode | mitigate | Mode is set to 1 (reject-only). Setting 2 (auto-accept) would be a privacy regression. The value is grep-verifiable in antumbra.js and checked by pref audit. |
| T-01-02-04 | Repudiation | antumbra.protection.mode | accept | This pref is new (antumbra. namespace); it is not in upstream StaticPrefList.yaml. The pref audit allowlist must explicitly cover antumbra.* prefixes. Plan 01-06 documents this rule. |

Note: No user data is handled in Milestone 1 repo files. Pref audit CI is the primary mitigation for silent protection removal.
</threat_model>
