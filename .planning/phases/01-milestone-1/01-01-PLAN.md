<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| patch files → Firefox tree | Patches are applied to a security-critical browser binary; any injected string or file becomes part of the shipped product. |
| branding strings → build output | Brand strings in brand.ftl and brand.properties appear verbatim in the shipped binary and installer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | Spoofing | brand.ftl / brand.properties | mitigate | CI branding-check job (section 10.3) verifies no Mozilla trademarks remain in strings on every push. |
| T-01-01-02 | Tampering | patches/0000-branding/ patch files | mitigate | Patches are committed to the antumbra-browser repo and tracked by git; any modification is visible in the commit history. The patch-apply-check CI job confirms patches apply cleanly to the pinned tag. |
| T-01-01-03 | Information Disclosure | startup.homepage_welcome_url | accept | URL points to a chrome:// resource served locally; no network request is made at first run by this pref. |
| T-01-01-04 | Elevation of Privilege | mozconfig build flags | mitigate | MOZ_REQUIRE_SIGNING is not set to 0 (D3); extension signing enforcement remains on. The mozconfig is committed to the repo; any change is reviewable. |

Note: No user data is handled in Milestone 1 repo files. The pref audit CI job (audit-prefs.py, plan 01-06) is the primary ongoing mitigation against silently disabled protections.
</threat_model>
