<objective>
Implement the three-mode protection system (Standard / Strict / Blackout) by creating per-mode pref delta files and a chrome JS patch that reads antumbra.protection.mode and applies the corresponding pref set and accent color.

Purpose: Protection modes are the user-facing expression of Antumbra's privacy controls. One setting should visibly change the browser's security posture and chrome color so a non-technical user can understand what is active. The first-run wizard (plan 01-05) writes antumbra.protection.mode; this plan implements what reads and acts on it.

Output:
- prefs/modes/standard.js, strict.js, blackout.js — the per-mode pref deltas
- patches/0200-modes/0200-01-mode-plumbing.patch — chrome JS patch that reads the mode pref and applies overrides + accent
</objective>

  The patch consists of two parts: a new JS module and a small addition to an existing front-end file.

  **Part A: New file browser/components/AntumbraMode.sys.mjs**

  Create this module in the Firefox tree (for patch purposes). The module:
  - Reads antumbra.protection.mode at startup.
  - Loads the matching mode's prefs (from the chrome:// URI where they are registered).
  - Applies them using Services.prefs.setUserPref / clearUserPref.
  - Exposes applyMode(modeName) for use by the first-run wizard (plan 01-05) and the shield panel.
  - Sets a CSS custom property --antumbra-mode-accent on the root element of the browser window.

  ```js
  /* This Source Code Form is subject to the terms of the Mozilla Public
   * License, v. 2.0. If a copy of the MPL was not distributed with this
   * file, You can obtain one at http://mozilla.org/MPL/2.0/. */

  /**
   * AntumbraMode.sys.mjs
   *
   * Reads antumbra.protection.mode and applies the corresponding pref delta
   * and chrome accent color. Called at browser startup and when the mode
   * is changed by the first-run wizard or the shield panel.
   *
   * Mode pref files are registered under chrome://antumbra/content/modes/
   * by the branding jar.mn (plan 01-01).
   */

  const lazy = {};

  ChromeUtils.defineESModuleGetters(lazy, {
    Services: "resource://gre/modules/Services.sys.mjs",
  });

  // Color tokens per BRANDING.md section 7 and mode table section 6.
  const MODE_ACCENT = {
    standard: "#8B95A3",  // --ash: neutral, nothing shouts.
    strict:   "#FFB020",  // --corona: amber ring with glow.
    blackout: "#000000",  // Pure black: removing color signals everything else removed too.
  };

  // Prefs that each mode overrides relative to the antumbra.js baseline.
  // Values must match prefs/modes/*.js.
  const MODE_PREFS = {
    standard: {
      "privacy.resistFingerprinting": false,
      "privacy.resistFingerprinting.letterboxing": false,
      "media.peerconnection.enabled": true,
    },
    strict: {
      "privacy.resistFingerprinting": false,
      "privacy.resistFingerprinting.letterboxing": false,
      "media.peerconnection.enabled": true,
      "privacy.query_stripping.strip_list": "utm_source utm_medium utm_campaign utm_term utm_content utm_id utm_cid utm_reader utm_place fbclid gclid gclsrc dclid msclkid yclid igshid mc_eid vero_id __s _hsenc _hsmi mkt_tok ck_subscriber_id s_cid twclid wbraid gbraid ttclid ScCid oly_enc_id oly_anon_id _openstat nb_src nb_klid",
    },
    blackout: {
      "privacy.resistFingerprinting": true,
      "privacy.resistFingerprinting.letterboxing": true,
      "media.peerconnection.enabled": false,
      "privacy.query_stripping.strip_list": "utm_source utm_medium utm_campaign utm_term utm_content utm_id utm_cid utm_reader utm_place fbclid gclid gclsrc dclid msclkid yclid igshid mc_eid vero_id __s _hsenc _hsmi mkt_tok ck_subscriber_id s_cid twclid wbraid gbraid ttclid ScCid oly_enc_id oly_anon_id _openstat nb_src nb_klid srsltid li_fat_id epik _ga _gl",
    },
  };

  export const AntumbraMode = {
    /**
     * Called at browser startup from BrowserGlue._onProfileStartup.
     * Applies the stored mode's prefs and returns the current mode name.
     */
    init() {
      const mode = Services.prefs.getStringPref(
        "antumbra.protection.mode",
        "standard"
      );
      this.applyMode(mode);
      return mode;
    },

    /**
     * Apply a named mode: write mode prefs and set the accent CSS variable.
     * @param {string} modeName - "standard", "strict", or "blackout"
     */
    applyMode(modeName) {
      const prefs = MODE_PREFS[modeName] ?? MODE_PREFS.standard;
      for (const [key, value] of Object.entries(prefs)) {
        if (typeof value === "boolean") {
          Services.prefs.setBoolPref(key, value);
        } else if (typeof value === "string") {
          Services.prefs.setStringPref(key, value);
        } else if (typeof value === "number") {
          Services.prefs.setIntPref(key, value);
        }
      }
      // Persist the mode choice.
      Services.prefs.setStringPref("antumbra.protection.mode", modeName);

      // Set accent for all open browser windows.
      this._applyAccentToWindows(modeName);
    },

    _applyAccentToWindows(modeName) {
      const accent = MODE_ACCENT[modeName] ?? MODE_ACCENT.standard;
      for (const win of Services.wm.getEnumerator("navigator:browser")) {
        win.document.documentElement.style.setProperty(
          "--antumbra-mode-accent",
          accent
        );
        win.document.documentElement.setAttribute(
          "antumbra-mode",
          modeName
        );
      }
    },

    /**
     * Per-site protection step-down: add the current domain to the
     * fingerprinting exception list and reload the tab.
     * Required in M1 per ROADMAP.md: "Per-site step-down: one click to relax."
     * @param {string} host - the hostname to exempt
     */
    exemptSite(host) {
      const current = Services.prefs.getStringPref(
        "privacy.resistFingerprinting.exemptedDomains",
        ""
      );
      const domains = current
        .split(",")
        .map(d => d.trim())
        .filter(Boolean);
      if (!domains.includes(host)) {
        domains.push(host);
        Services.prefs.setStringPref(
          "privacy.resistFingerprinting.exemptedDomains",
          domains.join(",")
        );
      }
    },

    /**
     * Remove a site from the exemption list.
     * @param {string} host
     */
    unexemptSite(host) {
      const current = Services.prefs.getStringPref(
        "privacy.resistFingerprinting.exemptedDomains",
        ""
      );
      const domains = current
        .split(",")
        .map(d => d.trim())
        .filter(d => d && d !== host);
      Services.prefs.setStringPref(
        "privacy.resistFingerprinting.exemptedDomains",
        domains.join(",")
      );
    },
  };
  ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| antumbra.protection.mode pref → AntumbraMode.init() | The mode pref is user-writeable (about:config); a user can change it. Mode switching is user-initiated by design. |
| AntumbraMode.applyMode() → Services.prefs.setBoolPref | Mode switching writes directly to the pref store; incorrect values could degrade privacy without user awareness. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-01 | Tampering | AntumbraMode mode pref writes | mitigate | MODE_PREFS is a static object in the patch; values are code-reviewed. The pref audit CI job checks that prefs written by mode switching exist in the upstream tree. |
| T-01-04-02 | Elevation of Privilege | exemptSite() writes exemptedDomains | accept | exemptSite is a user-initiated operation (one click in the shield panel). Writing to the exemption pref is the intended behavior. The function only appends; it does not clear the whole list. |
| T-01-04-03 | Tampering | blackout.js: privacy.resistFingerprinting = true | mitigate | Blackout mode sets RFP on; this is the intended security strengthening. Standard and Strict explicitly set it to false, so a mode switch does not leave stale RFP=true behind. |
| T-01-04-04 | Information Disclosure | MODE_ACCENT CSS variable visible to web content | accept | CSS custom properties on :root are readable by web content via getComputedStyle. The accent color reveals the protection mode. This is acceptable: the mode is user-chosen and the shield UI displays it explicitly. |

Note: No user data is handled in Milestone 1 repo files. Pref audit CI is the primary mitigation for inadvertent protection removal.
</threat_model>
